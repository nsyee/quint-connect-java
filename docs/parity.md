# Parity with the Rust reference implementation

This port is verified against the original Rust crate
[`quint-connect`](https://crates.io/crates/quint-connect) **v0.1.2**, following the
test strategy of [design.md §8](design.md). The tests are layered so that the
expensive ones (which need the Quint CLI and a Rust toolchain) are opt-in.

| Layer | What is compared | Needs | Where |
|-------|------------------|-------|-------|
| 1 | The exact `quint run` / `quint test` command lines (design.md §5.4) | nothing | `trace/RunConfigTest`, `trace/TestConfigTest`, `trace/QuintCliTest` |
| 2 | Replay result, unified diff, error message, `QUINT_SEED` hint and the full log against Rust golden fixtures | nothing | `runner/RustParityTest`, `parity/ParityTest` |
| 3 | ITF `states` generated by both runtimes for the same spec and seed | `quint`, `cargo` | `runner/CrossRuntimeParityTest` (`@Tag("parity")`) |
| 4 | Normalised stderr of both runtimes replaying that trace | `quint`, `cargo` | `runner/CrossRuntimeParityTest` (`@Tag("parity")`) |

Layers 1 and 2 run in the ordinary build (`./gradlew test` / `./gradlew check`).
Layers 3 and 4 are excluded from `test` and only run in the dedicated task:

```sh
./gradlew :quint-connect-core:parityTest
```

CI runs them in the `parity` job of `.github/workflows/ci.yml`.

## Reference harness

`parity/rust-harness` is a small Cargo crate that depends on `quint-connect = "=0.1.2"`
and defines the same tic-tac-toe drivers as `core/src/test/.../runner/TicTacToeDrivers.java`:

- `tictactoe` — a correct driver, expected to pass;
- `tictactoe_diverging` — forgets to switch turns after `MoveO`, expected to fail
  at trace 1 / step 2 with `State invariant failed`.

Both run `core/src/test/resources/spec/tictactoe.qnt` (copied verbatim from
upstream) with `max_samples = 1`.

`parity/run-rust-harness.sh <test> <out-dir> [seed] [verbosity]` builds the crate,
runs exactly one of those tests with `QUINT_SEED`/`QUINT_VERBOSE` set and
`NO_COLOR=1`, and captures into `<out-dir>`:

| File | Contents |
|------|----------|
| `commands.txt` | the `quint …` command line the crate spawned, with the temporary directory replaced by `<tmp>` |
| `run_0.itf.json` | the ITF trace it generated and replayed |
| `stderr.txt` | its raw stderr (the runner's log) |
| `status.txt` | `0` if the runner printed `[OK]`, `1` otherwise |

The command line and the ITF files are captured by `parity/bin/quint`, a shim that
is put first on `PATH` and forwards to the real `quint`.

## Golden fixtures (layer 2)

| Fixture | Contents |
|---------|----------|
| `core/src/test/resources/itf/rust/tictactoe_0x2a.itf.json` | ITF trace generated by Rust with `QUINT_SEED=0x2a` |
| `core/src/test/resources/parity/tictactoe_0x2a.command.txt` | command line Rust spawned |
| `core/src/test/resources/parity/tictactoe_0x2a.ok.stderr.txt` | Rust log, correct driver, `QUINT_VERBOSE=1` |
| `core/src/test/resources/parity/tictactoe_0x2a.diverging.stderr.txt` | Rust log, diverging driver, `QUINT_VERBOSE=1` |
| `core/src/test/resources/parity/PROVENANCE.txt` | versions and timestamp of the run that produced the above |

They were produced with:

- quint-connect (Rust) **0.1.2**
- Quint CLI **0.32.0** (`npm i -g @informalsystems/quint@0.32.0`)
- seed **`0x2a`**, verbosity **1**

### Regenerating

```sh
npm i -g @informalsystems/quint@0.32.0   # or the version you want to pin
rustup toolchain install stable          # any recent stable Rust
./parity/regenerate-goldens.sh           # QUINT_SEED=… to use another seed
```

The script runs both harness tests, checks that they generated the same
`states` (only `#meta` timestamps may differ), copies the fixtures listed above
and rewrites `PROVENANCE.txt`. Commit the result together with any change to
the harness or the spec. Note that a different Quint version may generate a
different trace for the same seed; the fixtures must then be regenerated and
`docs/parity.md` updated.

## What is normalised

`core/src/test/java/io/github/nsyee/quintconnect/parity/Parity.java` implements
the comparison. Only environment-dependent or deliberately different rendering
is normalised away:

- ANSI colour codes and `\r\n` line endings;
- the temporary directory in `--out-itf` (replaced by `<tmp>`);
- the `thread '…' panicked at …` trailer libtest appends after the Rust log;
- ITF `#meta` (timestamps, spec path as given on the command line);
- **inside the unified diff only**: Rust prints the two states with the
  `Debug` derive of the user's Rust struct (`GameState { next_turn: X, … }`),
  this port prints the canonical Quint-like rendering of the ITF value
  (`{ nextTurn: X, … }`). The diff headers (`--- specification`,
  `+++ implementation`, `@@`) and the changed `-`/`+` lines are compared after
  `snake_case → camelCase`; context lines are not.

Everything else — titles, `[Trace N]`, `[Step N]`, `Action taken:`,
`Nondet picks:`, `Next state:`, `[OK]`, `[FAIL]`, the `Reproduce this error
with \`QUINT_SEED=…\`` hint and blank-line layout — must match byte for byte.
